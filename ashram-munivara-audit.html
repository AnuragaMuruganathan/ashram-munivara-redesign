1. Priority findings

High

Reduced motion still downloads Three.js

components/HeroExperience.js:8 initializes reduced motion to false, while the real preference is read in a separate effect. The initialization effect can import Three.js before the preference updates.

Confirmed: with reduced motion enabled, the scene is hidden and no canvas is created, but /_next/static/chunks/3-d1rft_59n9h.js is still requested. Check the preference before any dynamic import, preferably using an unknown initial state or a direct matchMedia guard.

High

Three.js is lazy-split, not lazy-loaded by need

components/HeroExperience.js:47–55 dynamically imports Three.js and initializes the renderer immediately on mount. Every mobile visitor incurs download, parse, scene construction, texture upload, and GPU setup.

components/HeroExperience.js:54 also requests powerPreference: "high-performance", while desktop rendering targets 60 FPS. Defer work until after LCP or interaction, skip constrained/save-data devices, and consider CSS/SVG for this simple treatment.

High

106 spacing declarations exceed the 5px requirement

The stylesheet contains 106 explicit margin/padding/gap declarations above 5px, plus custom spacing tokens for larger gutters and section rhythm. The largest intentional values are 48px section spacing, 32px layout gaps, 24px grid gaps, and 20px event-card padding.

The full selector inventory is included below. Reduce both direct declarations and responsive/custom-token values if the 5px rule is literal, while retaining accessible 44px targets.

High

Practice cards have unexplained empty space

All four Yoga cards show a large blank lower region. The 2×2 grid stretches rows to match the Sadhana card rather than their own content. This looks like unused space, not intentional editorial whitespace.

Root cause: .practice-layout uses align-items: stretch and .path-grid uses two fractional rows. Match card height to content or rebalance the image/card composition without adding filler text.

High

A duplicate snapshot and diagnostic artifact should not deploy

.stitch/home.html is a 3.5 MB self-contained copy of the site with base64 images and styles. It duplicates the original deployment rather than serving a runtime purpose. hero-3d-check.png is another 227 KB diagnostic artifact in the project root.

Exclude migration/diagnostic artifacts from source deployment or store them outside the project. Do not delete the migration file blindly if it is still required for Stitch.

Medium

Responsive image coverage is incomplete

The Hero has one 630×630 source and no srcSet, so it can be soft above 630 CSS pixels or on high-DPR screens. Other images have only two candidates, and several sizes values use viewport width rather than the actual grid track and gutters.

Add correctly sized local candidates and align each sizes declaration with real rendered widths. Current files are already small; sizing is the priority, not another compression format.

3D fallback works: a simulated WebGL failure produced zero canvas elements and kept the original Hero image. The DOM image and texture share a URL, so fallback/progressive enhancement is sound. No play/pause button, slideshow, or slideshow numbering is present.

Implementation rule for the 5px requirement
  • Reduce every direct declaration above 5px to 0–5px, including responsive overrides.
  • Review token-based gutters, section padding, and gaps as well as literal declarations.

  • Recheck text wrapping and hierarchy after compaction. Do not trade overflow or congestion for smaller numbers.

4. Three.js and accessibility findings

High

Initial preference gate is too late

Reduced motion is checked after mount, but initialization is in a different effect. The first effect pass can already start the dynamic import. CSS hides the result but cannot undo the network request.

High

High-performance rendering is the default

The renderer explicitly requests high performance and targets 60 FPS on desktop. Shadows are enabled on non-coarse devices. Off-screen and hidden-tab pausing are implemented correctly, but active rendering still consumes GPU/battery.

Medium

Repeated layout reads

getBoundingClientRect() runs on every scroll event and pointer movement at components/HeroExperience.js:160–169. Passive listeners do not remove this layout work.

Cache bounds and refresh from the existing ResizeObserver, or schedule updates through one requestAnimationFrame.

Medium

External-link announcements vary

Header/footer social links announce new tabs, while community updates, schedule confirmation, stay/event inquiries, directions, and WhatsApp contacts use target="_blank" without the same disclosure.

Low

Icon and year maintenance

The Apple touch icon reuses a 146×141 logo rather than a dedicated 180×180 image. The prerendered copyright year can become stale between deployments.

Pass

Accessibility fundamentals are strong

Skip link, focusable main target, visible focus styles, meaningful image alternatives, decorative logo alternatives, mobile aria-expanded/aria-controls, initial menu focus, Escape restoration, and reduced-motion CSS are all present.

What is working

  • All non-priority images lazy-load with asynchronous decoding. Only the Hero is eager/high priority.
  • Image dimensions and parent aspect ratios reserve layout space and reduce layout shift.
  • Fingerprinted WebP files receive public, max-age=31536000, immutable, appropriate for content-hashed URLs.
  • The unversioned logo is not covered by that immutable rule, which is correct.
  • images.unoptimized: true already exists in next.config.mjs:2. Native images already implement manual responsive delivery.
Deployment artifacts: node_modules is about 408 MB and .next about 103 MB locally, but both are excluded from source control and are not the intended deployment footprint. The separate 3.5 MB .stitch/home.html and 227 KB diagnostic screenshot should be handled explicitly so they do not become accidental source artifacts.

6. Optimization plan for later implementation

  1. Fix the 3D gate first. Do not import Three.js until reduced motion is explicitly false. Skip save-data/constrained devices and defer initialization until after LCP or an appropriate interaction.
  2. Reduce rendering work. Prefer automatic power mode, cap desktop quality, retain mobile 30 FPS/DPR limits and off-screen pausing, and cache scroll/pointer geometry. Evaluate CSS/SVG for this simple scene if WebGL is not essential.
  3. Apply the spacing rule. Reduce all 106 declarations and token-based gutters above 5px, then visually verify that text does not collide and controls remain usable.
  4. Rebalance Practice. Use content-height cards or a different image/card ratio. Do not add filler text to occupy empty space.
  5. Improve responsive images locally. Add 315/480px Hero candidates for small screens and 960/1260px candidates for wide/high-DPR use. Add larger candidates only for images whose actual layout requires them. Derive every sizes value from the real grid track.
  6. Keep the existing configuration merge. Preserve poweredByHeader and the custom headers() function when retaining images: { unoptimized: true }. No configuration change is required for this requirement.
  7. Exclude migration and diagnostic artifacts. Decide whether .stitch/home.html must be retained for Stitch. If it is only a migration artifact, keep it out of deployment. Remove diagnostic screenshots from source deployment.
  8. Finish UX maintenance. Add a square Apple touch icon, standardize new-tab labels, maintain the copyright year, and show verified event dates or a clear unpublished state.
  9. Validate on Vercel preview. Confirm actual Brotli/gzip transfer sizes, LCP on slow networks, reduced-motion producing no Three.js request, WebGL failure fallback, keyboard navigation, and immutable WebP response headers.
